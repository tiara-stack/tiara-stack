## Generate the draft

Run `/room_order manual` with the underscore included. It accepts these optional inputs:

- `channel_name`.
- `hour`.
- `heal` for the healer-needed value.
- `server_id`.

TiaraBot resolves the running room/hour, generates an order from sheet data, and posts an interactive draft in the running room.
The complete draft appears immediately and may briefly include the muted line **Controls are being
prepared...** while TiaraBot registers it. TiaraBot then adds the **Previous**, **Next**, and
**Send** controls. Wait for those controls before acting.

## Read the monitor handoff

Room order labels the current monitor with **`Monis:`**. When TiaraBot can read the adjacent
Schedule Monitor Assignment for the same running room, it shows the transition as well:

- **`Monis: In Airi · Out Miku`** when both assignments differ.
- **`Monis: In Airi`** when the previous schedule hour is present but unassigned.
- **`Monis: Out Miku`** when the current schedule hour is unassigned and the previous assignment is known.
- **`Monis: Airi`** when the previous schedule hour is unavailable or the assignment is unchanged.
- **No `Monis:` line** when neither the current assignment nor a known previous assignment is available.

The current monitor remains part of the canonical room-order record. The prior monitor is derived
from the authoritative schedule sheet whenever navigation, Send, or Pin rebuilds the message, so
editing the sheet affects a later rebuild. TiaraBot does not add prior-monitor history to the room-
order database record or run a migration to backfill it.

## Check the event format

For TiaraBot operations, World Link uses the same room-order flow as Marathon.

For CC (Cheerful Carnival), inspect each candidate order’s combined total before publishing it. Select an order that stays within the threshold your server uses to avoid slower matchmaking. TiaraBot does not replace the mana/moni decision on whether that total is acceptable.

## Select and publish

- **Previous / Next** moves through generated order variants.
- **Send** on a normal draft publishes the selected room order and attempts to pin it.
- A tentative order produced during check-in has a separate **Pin** action and cannot use normal Send.

### Tentative room order

Check-in can prepare a tentative order with navigation and a dedicated **Pin** action.
The complete order appears immediately with the same muted preparation line until TiaraBot adds
the interactive controls.

<TentativeRoomOrderExample />

After **Pin**, TiaraBot privately acknowledges the button press. The original tentative message is
kept in the channel without its controls and is pinned in place.

<TentativeRoomOrderPinResultExample />

If TiaraBot reports that delivery succeeded but pinning failed, pin the published message manually and avoid sending a duplicate. If the order is stale after a replacement, update the source schedule through the established process and generate it again.

Room order is not a filler position-claim form. Fillers read the selected/pinned result.
