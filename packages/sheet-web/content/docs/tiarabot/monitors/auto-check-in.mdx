## Enable automatic check-in

Use `/server set auto_checkin` to enable automatic check-in for the event server. Confirm the schedule
sheet and each running channel’s `name` and `checkin_channel` configuration before relying on it.
Optionally configure `/server set monitor_channel channel:#mana-moni` for shared monitor summaries
and handoff check-ins.

## What happens at minute 45

At minute 45 of each hour, TiaraBot processes the next due check-in for configured running channels. For each check-in, it:

1. posts the filler-facing **Check in** prompt in the configured check-in channel.
2. sends enabled filler check-in DMs.
3. posts the monitor summary in the configured mana/moni channel, or in the running channel when no monitor channel is configured.
4. asks a newly assigned linked monitor to check in and sends their enabled monitor DM.
5. automatically posts a tentative room order in the running channel when enough fills are available.

Manual check-in remains unchanged and returns its monitor summary through the command response.

### Check-in prompt

The filler-facing prompt is a new public message in the configured check-in channel.
The complete prompt appears immediately so its mentions notify fillers. It may briefly include the
muted line **Controls are being prepared...** while TiaraBot registers the message, then updates in
place with the **Check in** button.

### Automatic monitor summary and handoff

With `monitor_channel` configured, TiaraBot posts one combined message there for every running room
and hour, even when there are no new fillers. The embed identifies the running room and hour and
contains the empty-slot and Out/Stay/In result.

When the linked monitor differs from the immediately previous hour's assignment in that same room,
TiaraBot mentions them and adds **Check in**:

room. Repeated clicks do not announce again.

If the same monitor is assigned in the same room for the immediately previous hour, TiaraBot mentions
them as continuing. There is no button, DM, or running-room announcement:

Continuation is based on schedule assignments and is scoped to the running room. A room change or a
break in the schedule requires another check-in. An unassigned or unresolved monitor still gets a
summary and the existing warning, without a ping or button.

Without `monitor_channel`, TiaraBot preserves the legacy behavior: the summary is posted in each
running room, no monitor check-in button is created, and the existing monitor DM remains enabled.

When a newly assigned monitor has enabled monitor notifications, TiaraBot sends this DM after posting the

## Operate the automatic result

At minute 45, review the configured mana/moni channel, or the running room when no monitor channel is
configured. Newly assigned monitors can open the mana/moni channel from their DM when notifications are
enabled. Review the empty-slot count and the Out/Stay/In movement, check in when prompted, then use the
tentative room-order controls and your server’s standby/emergency process as needed. Continuing monitors
do not receive a new DM or check-in prompt.

## Automatic lockdown-role cleanup at minute 15

For every server with automatic check-in enabled, TiaraBot also runs lockdown-role cleanup at minute 15 of each hour. For each configured running channel, it reads the current hour’s scheduled fills and removes the channel’s lockdown role from members who are not in that fill list.

Channels without a configured lockdown role are skipped. Before minute 40, use `/kick manual` for ad-hoc cleanup when the schedule or room assignment changes after the automatic pass. From minute 40 through minute 59, TiaraBot rejects manual cleanup to protect fills scheduled through minute 00 of the next hour.

## Use server-controlled timing instead

If the server should not open at minute 45, disable auto check-in and use [`/checkin manual`](/docs/tiarabot/monitors/check-ins) at the server’s chosen time. Manual check-in creates the same filler-facing button and can also prepare a tentative room order, but its moni summary is returned through the invoking command response.
